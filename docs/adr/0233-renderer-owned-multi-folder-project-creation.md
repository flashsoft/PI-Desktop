# ADR 0233: 渲染进程拥有的多文件夹项目创建

- Status: Accepted; behavior superseded in part by ADR 0249
- Date: 2026-09-12
- Deciders: PI-Desktop desktop UI maintainers
- Amends: ADR 0011, ADR 0016

## Context

现有的项目入口打开一个原生目录选择器，并激活它返回的单个目录。重新
设计的 Create project 流程需要收集项目名称，并支持在一次操作中选择
多个本地文件夹，同时保留 host-core 只暴露一个当前可见工作区的边界。

把选定的文件夹当作一个新的宿主工作区来对待，会扩大运行时所有权模
型，并让会话、指令和文件访问语义产生歧义。把除第一个之外的所有文
件夹当作临时 UI 状态，又会丢失用户明确的项目选择。

## Decision

1. 渲染进程拥有 Create project 对话框，包括项目名称、已选文件夹列
   表、移除动作、主文件夹标记、校验、焦点处理和创建状态。
2. 主进程暴露 `project/pickFolders` 作为一个窄的原生能力。它可以打
   开多选目录选择器并返回绝对路径；它不改变活动的宿主工作区。
3. 第一个选中的文件夹是一个逻辑项目分组的主根目录。创建会激活它，
   并把输入的显示名称应用到该分组；其他每个选中的文件夹作为分组根
   目录保留，而不是独立的项目标签页。宿主仍然只把主根目录暴露为当
   前活动工作区。
4. 侧边栏和设置中的项目入口使用同一个对话框和创建动作。

## Consequences

- 用户可以为项目命名并添加多个文件夹，而无需重复项目入口流程。
- 额外的文件夹作为同一命名项目分组的持久根目录保持可用。
- 除了增量式的目录选择器能力之外，宿主 RPC 和安全边界保持不变；切
  换标签页仍然通过现有的项目激活路径改变那一个活动宿主工作区。
- 第一个文件夹的位置是有意义的。重排或选择不同的主文件夹有意不在
  本次迭代范围内。

## Alternatives considered

- **在宿主工作区中添加多根执行：** 被拒绝，因为它改变冻结的“一个
  可见工作区”模型，并需要单独的收容和权限设计。ADR 0249 在不扩大
  内置工具根目录的情况下添加了逻辑分组所有权。
- **让原生选择器作为整个 UI：** 被拒绝，因为它无法收集项目名称、
  暴露已选文件夹移除，或提供一致的类 ChatGPT 创建界面。
- **用单独的用户操作打开每个文件夹：** 被拒绝，因为它让多文件夹设
  置变得缓慢，并在创建期间隐藏了所选文件夹之间的关系。
